# ConsensusWeaver

## 描述

ConsensusWeaver 是一个多 AI 平台答案聚合工具。它通过 MCP Server 并行向多个中文 AI WebApp（豆包、智谱清言、DeepSeek、千问、元宝）提问，**收集所有能够获取到的答案**，然后由 TRAE 进行整合、对比与合成，最终输出：

- 各平台答案的**共识内容**
- 不同平台之间的**主要分歧点**
- 失败平台的**简要原因**

不需要 5 个平台全部成功，只要**达到 3/5 成功**即可进入汇总阶段。

## 调用方式

当用户在 TRAEwork 中提出需要多角度参考、对比或综合的问题时，自动调用本 Skill。

典型触发场景：

- 用户问 "如何学习 Python？"
- 用户问 "比较一下 Vue 和 React"
- 用户问 "给我几个不同的方案"
- 用户明确说 "用 ConsensusWeaver 问一下"

## 工作流

### 1. 接收用户问题

直接提取用户当前消息中的问题内容，不需要二次确认。

### 2. 调用 ConsensusWeaver MCP 的 `ask_ai` 工具

使用以下参数调用：

```json
{
  "question": "<用户原始问题>",
  "platforms": ["doubao", "deepseek", "chatglm", "qianwen", "yuanbao"],
  "timeout": 120,
  "min_success": 3
}
```

默认同时向 5 个平台提问，`min_success` 固定为 3。只要成功数 ≥ 3，即视为可进入下一步汇总。

### 3. 读取 `ask_ai` 返回结果

解析返回的 JSON，重点关注：

- `success`：整体是否达到 `min_success` 门槛
- `success_count` / `total_count`：成功平台数量
- `results`：每个平台的原始回答
  - `platform_name`：平台名称
  - `status`：`success` 或 `failed`
  - `answer`：平台返回的原始文本
  - `error`：失败原因

### 4. 合成最终答案

**只使用 `status` 为 `success` 的回答。** 合成时遵循以下规则：

1. **简要复述用户问题**，说明本次汇总基于几个成功平台的答案。
2. **提取共识**：找出多个平台都认同的核心观点，作为答案主干。
3. **保留互补信息**：某个平台独有的、有价值的信息，分点列出（最多 5 点）。
4. **标注分歧**：如果不同平台给出相互矛盾的观点，明确指出分歧点。
5. **忽略噪音**：如果某平台回答为空、错误或与主题无关，直接忽略，不纳入汇总。
6. **失败说明**：在末尾用一句话列出失败平台及其简要原因（如超时、未登录、提取失败等）。

### 5. 输出格式

```markdown
## 综合回答

<基于成功平台答案提炼的共识内容，分点清晰>

## 不同角度的补充

- <平台 A 独有的观点或细节>
- <平台 B 独有的观点或细节>
（最多 5 点，没有则省略此节）

## 分歧点

- <平台 X 认为…，而平台 Y 认为…>
（没有明显分歧则省略此节）

---

## 参考来源

- DeepSeek：成功，<一句话总结其贡献>
- 元宝：成功，<一句话总结其贡献>
- 豆包：失败，<简要失败原因>
- 智谱清言：失败，<简要失败原因>
- 千问：失败，<简要失败原因>
```

## 异常处理

- 如果 `ask_ai` 返回 `success: false`（即成功数 < 3），向用户说明当前平台可用性不足，展示失败的详细原因，并建议检查登录状态或稍后再试。
- 如果只有一个或两个平台成功，直接输出这些可用答案的要点，并提示用户当前聚合结果有限。
- 如果所有平台均失败，建议用户检查 MCP Server 状态或网络连接。

## 注意事项

- 不要修改用户的原始问题。
- 不要在调用 `ask_ai` 前询问用户是否确认。
- 合成时应优先保证信息的准确性和可读性，而不是简单拼接。
- **核心目标**：从所有可用答案中提炼共识，而不是让每个平台都完美回答。
